# Invoicer

Single-user, self-hosted Italian e-invoicing (FatturaPA) PWA on Cloudflare (Worker + D1 +
Cron), sending to the SdI through the owner's PEC mailbox (SMTP) and polling it (IMAP). Spec: docs/specs/invoicer.md. Plan and progress:
docs/plans/invoicer.md.

## Commands

Keep this list in sync with `package.json`. Requires Node 22+ and pnpm (see `packageManager`).

- Install: `pnpm install` (CI: `pnpm install --frozen-lockfile`); local secrets: `cp .dev.vars.example .dev.vars`
- Dev server: `pnpm dev` (Vite + local Worker, D1; PEC, Resend and push off or mocked)
- Build: `pnpm build`; preview the build (service worker on): `pnpm preview`
- All unit/integration tests (dot reporter): `pnpm test`
- One Vitest project: `pnpm vitest run --project shared|worker|client --reporter=dot`
- Single test file, failures only: `pnpm vitest run <path/to/file.test.ts> --reporter=dot`
- E2E: `pnpm test:e2e` (Playwright; builds with `E2E_WORKER=1` and serves `vite preview` on a throwaway D1 in `.wrangler/e2e-state`; overwrites `dist/`, so run `pnpm build && pnpm check:bundle` after it). One flow file: `pnpm exec playwright test tests/e2e/flows.spec.ts --project=flows --no-deps`
- Lint (Biome): `pnpm lint`; auto-fix and format: `pnpm format`
- Typecheck: `pnpm typecheck` (client, worker and node tsconfigs)
- Bundle check (Worker size, client-only libraries): `pnpm check:bundle` (after `pnpm build`)
- DB: `pnpm db:generate`, `pnpm db:migrate:local`, `pnpm db:migrate:remote`, `pnpm db:seed`
- Deploy: `pnpm run deploy` (`pnpm deploy` is a different built-in command); normally via GitHub Actions on push to `main`

## Folders

- `src/client/` — React SPA (`routes/`, `components/` (Home top strip: `dashboard-strip.tsx`), shadcn/ui in `components/ui/`, `lib/`, `i18n/`, `pdf/` invoice PDF: model, `@react-pdf/renderer` document, render and store helper, `pdf-text.ts` test text reader, `import/` browser-side invoice file reading: `p7m.ts` pkijs/asn1js, `eml.ts` raw PEC message, `zip.ts` fflate, `read.ts`, `summary.ts`, `run.ts` import runner, `clients-csv.ts` papaparse FiC clients CSV)
- `src/worker/` — Hono API (`app.ts`, `env.ts`, `security.ts`, `routes/`, `jobs/`, `auth/` Better Auth + owner setup + session middleware); `pec/` (IMAP client, envelope parsing and classifier, SMTP send, `poll.ts` cron poll, `effects.ts` receipt matching and transitions); `outbox.ts` (notification rows and outbox delivery); `jobs/` (cron: `scheduled.ts` runs the `dailyTasks` once per Rome day, each on its own; overdue, `job-runs.ts`); `pec/status.ts` (the mailbox login-failure status); `routes/received.ts` (received invoices: list, original, parse result, payment, manual import); `invoices/import.ts` (historic issued invoice import); `storage.ts` (file storage interface, D1 BLOB backend); `onboarding.ts` (setup checklist facts, `loadSendReadiness` gate that send must check); `email/` (courtesy email: `resend.ts` plain-fetch Resend call, `courtesy.ts` draft and send + `email_log`, `deliver.ts` outbox rows by mode); `invoices/` (invoice store, guarded number reserve/release in one D1 batch, per numbering series); `push/` (`send.ts` VAPID + RFC 8291 sender with the `pushDeps` test seam, `deliver.ts` pushes derived from the `notifications` rows, `text.ts` localized text from the `notifications` keys of `locales/*/common.json`, `settings.ts` language and per-type switches)
- `src/shared/` — pure code used by both: errors (problem+json), CSP, formatting, invoice states; `profile.ts` (profile and email-settings validation, RF codes), `pdf-name.ts` (PDF and preview download names; the XML keeps its SdI name), `tax.ts` (the owner's regime, cassa and ritenuta: schemas shared by Tax details, invoices and the client flags), `onboarding.ts` (checklist, `sendReadiness`), `numbering.ts` (numbering series: prefix/suffix rules, `formatInvoiceNumber`, `matchSeries`), `notifications.ts` (notification types, `notificationPath` deep links, `fillTemplate`), `invoice.ts` (editor schemas, issuing rules, issuance-term warning, state rules), `courtesy-email.ts` (subject and body templates from `locales/{en,it}/email.json`), `payment-terms.ts` (terms kinds: invoice date, 15/30/60 end of month, custom days; `dueDate`; reads older shapes), `mailbox-status.ts` (mailbox status type), `totals/` (integer-cent totals engine, money parsing, natura legal texts, option labels in `labels.ts`) and `fixtures/` (invoice fixtures a-g with hand-computed expected totals, also reused by XML/PDF tests); `import.ts` (import summaries, skip reasons, upload header), `received.ts` (received invoice record), `limits.ts` (file size cap); later FatturaPA XML, channel
- `src/db/` — Drizzle schema (`schema.ts`) and local seed; `migrations/` — D1 migrations generated by `pnpm db:generate` (never hand-edited; the schema test applies them to a clean D1)
- `locales/{en,it}/` — i18n resources (`common.json` UI and PDF, `email.json` courtesy email templates the Worker fills itself)
- `public/` — static assets, icons, `_headers` (CSP for the SPA)
- `scripts/` — CI helpers (bundle check, wrangler config rendering)
- `assets/xsd/` — vendored official FatturaPA XSD v1.2.3 (`Schema_VFPR12_v1.2.3.xsd`, SHA-256 and source in its README) and the W3C xmldsig schema it imports
- `tests/` — Playwright E2E (`e2e/`: `flows.spec.ts`, `support.ts`, and `worker/entry.ts`, the E2E-only Worker entry with a fake PEC mailbox and captured Resend behind `/api/e2e/*`, never in the production bundle), cross-cutting tests (CSP, browser error reporting), PEC/IMAP fixtures live next to the code (`src/worker/pec/*fixtures.ts`)
- `docs/` — specs, plans, notes; `.github/workflows/` — CI and deploy

## Conventions

- Everything in the repo is in English; user-facing text only through i18n (`en` base, `it`).
- Selects and dates: use `Select` and `DatePicker` from `components/ui` (never a bare `<select>` or `<Input type="date">`). Pointer devices get Radix Select / a react-day-picker popover; coarse-pointer phones and jsdom get the native control (`lib/use-native-controls.ts`); tests for the rich path call `setPointer(false)` from `lib/pointer-test-support.ts`. Do not use `Select.Viewport` (inline `<style>`, blocked by the CSP). Date values are `YYYY-MM-DD` strings.
- Money is integer cents in domain code; dates for numbering use Europe/Rome. Numbers are per numbering series (`numbering_series`, prefix + progressive + suffix, see docs/notes/invoice-numbering.md); `number_int` is the progressive, `number_raw` the printed number.
- Unit/integration tests live next to the code as `*.test.ts(x)`; Vitest projects: `shared` (node),
  `worker` (workerd via `@cloudflare/vitest-pool-workers`), `client` (jsdom).
- Errors: API failures are problem+json built with `ApiError` (`src/shared/errors.ts`); a missing
  secret names the variable and its `wrangler secret put` fix. Every error code has a README anchor.
- Routes are code-based TanStack Router in `src/client/router.tsx`; the Invoices list (`/invoices`, `routes/invoices.tsx`) keeps its filters in the URL search params and gets list and recap from `GET /api/invoices?scope=all`; status label/colour/icon live
  only in `src/client/lib/status.ts`; use the base components in `components/ui/` (`Disclosure` for collapsible sections).
- Page actions: the invoice editor's title row (`Page` `aside`, `MenuButton` in `components/ui/menu-button.tsx` for menus; no menu library) has in view mode, before finalisation, the primary Finalize button, then an icon-only "⋯" `MenuButton` ("More actions": Edit, Duplicate, credit note, payment via `components/payment-action.tsx`, Send email via `components/courtesy-email.tsx` (offer card, history timeline and editable preview sheet), Download PDF/XML, Delete with confirmation, as the state allows); edit mode (a saved invoice after Edit; new and duplicated invoices open in it) has no title actions and Cancel / Save under the form; the sticky bar shows totals only. A number or status for the title row goes in `Page`'s `subtitle` slot.
- Invoice editor: Save never validates (`parseInvoiceDraft`; the raw form is kept in `invoices.editor_form`); every check runs in Finalize (`SendSheet` with `preflight`, `lib/finalize-checks.ts`). Every Save button is disabled until the form changed (`useDirty`, `lib/use-dirty.ts`); a page's back link is `Page`'s `back` prop with a constant from `lib/back-links.ts`. `/import` takes the page it was opened from in the `from` search param (`importBackLink`); a link to `/import` must pass it.
- Transient feedback (saved, action failed) goes through `toast()` from `components/ui/toast.tsx`, never a page banner; `Banner` is for persistent page messages.
- Security: the CSP in `src/shared/csp.ts` must equal `public/_headers` (tested); no inline script or eval (`script-src 'self' 'wasm-unsafe-eval'`: the extra source only lets xmllint-wasm compile),
  `connect-src 'self'`; state-changing `/api/*` calls need a matching `Origin`.
- Auth: Better Auth (passkey + twoFactor) on D1; sign-up is disabled, the owner is created only by
  `POST /api/setup` with `SETUP_TOKEN`. Every `/api/*` route needs a session except the public list
  in `src/worker/auth/session.ts`. Worker auth tests use `src/worker/auth/test-helpers.ts` (cookie
  client, TOTP, virtual authenticator). Better Auth tables follow its model names in `src/db/schema.ts`.
- Secrets (`PEC_USERNAME`/`PEC_PASSWORD`, Resend key, VAPID key, setup token) are Worker
  secrets only: never in D1, tracked files or API responses. Owner-specific values (domain,
  sender, resource IDs) come from env or untracked config; `wrangler.jsonc` holds placeholders
  that CI fills (`scripts/render-wrangler-config.mjs`).
- Biome ignores Markdown; do not run it over `docs/`. Dependency versions are pinned exactly.
- The PEC password gives full mailbox access (one password for IMAP, SMTP, webmail); the IMAP client
  is read-only by design (EXAMINE, PEEK, no delete). One cron trigger only (`*/10 * * * *`): every run polls the mailbox; the daily jobs run
  from it at 09:00 Europe/Rome, once per Rome day (`shouldRunDaily` in `src/shared/cron.ts`).
- FatturaPA: XSD validation (`xmllint-wasm`, `src/shared/fatturapa/validate.ts`) runs only in the browser and in tests, never in the Worker; do not import it from Worker code or from the `fatturapa` barrel. The XML is always in euro (a non-EUR invoice needs an exchange rate). File names are `IT<vat>_<5 base-36 digits>.xml`, one new progressive per transmission attempt.
- `@react-pdf/renderer` is loaded only through dynamic import in `src/client/pdf/render.ts` (client-only, never in the Worker bundle: `pnpm check:bundle`); PDF text lives in the `pdf` keys of `locales/{en,it}/common.json`. yoga-layout's inlined WebAssembly is fed to Emscripten as bytes by the `yogaWasmFromBytes` plugin in `vite.config.ts` (its `data:` fetch would break `connect-src 'self'`); PDF tests run in `// @vitest-environment node` and read the text back by inflating the streams.
- Invoice files (XML, P7M, ZIP, raw PEC `.eml`): the Worker never parses them. The browser reads them (`src/client/import/`; pkijs, fflate, papaparse stay out of the Worker bundle) and sends the original as the raw body with a JSON summary in the `X-Invoicer-Meta` header (`POST /api/received/import`, `POST /api/invoices/import`); a polled received invoice stays `parse_status = pending` until the Received page reports `PUT /api/received/:id/parsed`. Imported issued invoices are `source = imported`, state `delivered`, read-only, and their number blocks reuse like any issued number.
- Push: derived from the `notifications` rows by `processPushNotifications` on every cron tick (`push_sent_at` settles a row; at most 3 rows and 5 devices per tick, nothing older than 1 hour); the owner's language is `settings.ui_language` (the client PUTs it), switched-off types are `settings.push_disabled_types`; `push_subscriptions` is never exported. New notification types go in `src/shared/notifications.ts` and the `notifications.<type>` locale keys (UI strings of the list and settings are in `notificationsPage`). The service worker imports `public/push-sw.js`.
- Daily jobs (`src/worker/jobs/scheduled.ts` `dailyTasks`) must be idempotent and bounded per run (50 rows); recurring invoices were removed on 2026-11-04 (see the plan Decisions). A new notification type needs its `notifications.<type>` keys in both locales, an entry in `NOTIFICATION_TYPES` and a fixture in `routes/notifications.test.tsx`.
- Free-plan limits matter: 10 ms CPU per request; heavy work (XML/XSD, PDF, P7M) runs in the browser.
- Send flow: the Worker hashes the stored XML itself and verifies the assertion before `channelDeps.create` (`src/worker/channel.ts`) can open any socket; the attempt is claimed `unknown` (with its Message-ID) before the SMTP session and set back to `none` only on a definite refusal. Retries after an unknown outcome need 15 minutes and a new file progressive. Test seams: `channelDeps`, `smtpDeps` (`pec/smtp.ts`). `SEND_CHANNEL=mock` is localhost-only. The live PEC test (`pec/live.test.ts`) runs only with `PEC_LIVE=1`.
- Courtesy email: the Worker calls Resend with plain `fetch` (`resendDeps.fetch` is the test seam; no automated test reaches Resend). One `email` outbox row per invoice and attempt; `RESEND_API_KEY` is read through `requireSecrets(env, "email")`. A row is `skipped` (off, not configured, queued before enabling, no recipient), `asked` (mode ask, waits for Send / Skip) or sent with the row id as `Idempotency-Key`; a failure is logged, notified and never retried automatically.
- Mailbox polling (`pec/poll.ts`): one D1 batch per message (row, guarded state-rank transition for the latest attempt only, events, outbox, cursor); a retry after an unknown send also needs a successful poll after the quiet period. Tests use `pec/fake-mailbox.ts` (stateful fake IMAP), `receipt-fixtures.ts` builders and `test-support.ts`.
- Secrets audit: `src/worker/secrets-audit.test.ts` searches API responses, D1 rows, the export and logs for every secret value; a new place that stores, returns or logs data from a server, Resend or push must keep it green. The browser has no error-reporting channel (`tests/browser-error-reports.test.ts`).
- No automated test talks to the real SdI; use recorded IMAP/SMTP fixtures and the fake socket (`src/worker/pec/fake-socket.ts`).
